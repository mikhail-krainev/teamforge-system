# ADR-0007. Валидация: Ajv по схемам OpenAPI на HTTP-границе, zod для остальных границ

Статус: принято. Дата: 2026-10-12. Фаза 3.

## Контекст

Правила для агентов: входные данные проверяются схемой на границе системы; spec 5.3: лишние поля отбрасываются. Границ несколько: HTTP-запросы, переменные окружения, вебхуки и ответы GitHub API, файлы сценариев, результаты resume-worker, данные задач очередей. Нужно выбрать между class-validator (стандарт NestJS) и zod, не дублируя контракт OpenAPI (ADR-0006).

## Решение

- HTTP: схемы запросов берутся из `openapi.json` (OpenAPI 3.1 = JSON Schema 2020-12) и компилируются Ajv (`ajv/dist/2020` + `ajv-formats`) при старте процесса. `ValidationGuard` выбирает схему по `@Operation('<operationId>')`. Настройки: `removeAdditional: 'all'`, `allErrors: true`, `coerceTypes` только для path/query. Ошибка - 400 `VALIDATION_FAILED` с JSON Pointer.
- Всё, что не описано контрактом HTTP, проверяется **zod**: окружение (`platform/config.ts`, fail-fast при старте), полезные нагрузки вебхуков и ответы GitHub API (недоверенные данные третьей стороны), файлы сценариев (структура `docs/playbooks.md` 2.1; доменные правила FR-PLAY-02 - кодом поверх), результат resume-worker, данные задач BullMQ.
- Доменные правила (уникальность приоритетов, справочники, условия ритуала) - в сервисах, ответ 422/409.
- class-validator не используется.

## Последствия

- Плюсы: HTTP-валидация не может разойтись с контрактом - это та же схема; zod даёт типы из схем там, где контракта нет; одно правило "схема на каждой границе".
- Минусы: два инструмента; сообщения Ajv приходится переводить в `errors[]` problem+json; Ajv-форматы (`uri`, `email`, `date`) - через `ajv-formats`.

## Альтернативы

- class-validator + class-transformer: DTO-классы дублируют OpenAPI вручную и расходятся с ним; медленнее; декораторы не покрывают все конструкции JSON Schema. Отклонено.
- zod для HTTP с генерацией zod-схем из OpenAPI (orval, openapi-zod-client): лишний шаг генерации и риск неточного перевода конструкций 3.1 (`type: [x, null]`, `const`). Отклонено.
- Fastify-валидация на уровне маршрутов: Nest регистрирует маршруты сам; привязка схем через `operationId` проще и не зависит от адаптера. Отклонено.
