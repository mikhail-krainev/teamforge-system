# ADR-0006. OpenAPI - источник истины, генерация типов openapi-typescript

Статус: принято. Дата: 2026-10-12. Фаза 3. Обновлено в фазе 3 по аудиту безопасности (`docs/security-review-phase3.md`, SEC-03).

## Контекст

Оркестратор: `packages/shared` содержит типы, сгенерированные из контракта OpenAPI; после фазы 3 контракт меняется только через оркестратора. web и api пишутся разными агентами параллельно; расхождение типов между ними должно ловиться CI, а не в браузере.

## Решение

- Контракт-первым: `docs/api/openapi.yaml` (OpenAPI 3.1) - единственный источник; код сервера не генерирует спецификацию (без `@nestjs/swagger`-декораторов как источника).
- `pnpm --filter shared run generate`: `@redocly/cli lint` -> `redocly bundle` в `packages/shared/openapi.json` -> `openapi-typescript` в `packages/shared/src/generated/api.ts`; хелперы `Schema<N>`, `Body<Op>`, `Ok<Op>`.
- web: `openapi-fetch` (`createClient<paths>`) + TanStack Query; ошибки по `Problem.code`.
- api: обработчики помечены `@Operation('<operationId>')`, типы тела и ответа берутся из `operations`; валидация входа по той же схеме (ADR-0007); контрактные тесты проверяют ответы схемой.
- CI: генерация + `git diff --exit-code`; `oasdiff breaking` против `main` (ломающее изменение блокирует слияние до решения оркестратора).
- Изменения контракта только добавляющие (новые необязательные поля, новые коды ошибок в `ErrorCode`, новые операции); удаление и смена типа - через новый эндпоинт и вывод старого из употребления.
- Каждая операция несёт `x-authz` (`actor`, `chain` идентификаторов пути, `rule`); CI отклоняет операцию без него и генерирует из него отрицательные тесты доступа и IDOR (ADR-0018, SEC-03).

## Последствия

- Плюсы: одна спецификация для типов клиента, типов сервера и валидации; изменения контракта видны в диффе одного файла.
- Минусы: правка контракта требует регенерации; рукописные части (WebSocket-сообщения) лежат рядом и не проверяются генератором.

## Альтернативы

- Код-первым (`@nestjs/swagger` из DTO): контракт следует за реализацией, а не наоборот; два агента не могут начать одновременно. Отклонено.
- orval / openapi-generator (полные клиенты и zod): больше генерируемого кода и зависимостей; `openapi-fetch` даёт типизированный клиент на основе одних типов. Отклонено.
- tRPC / ts-rest: отказ от OpenAPI как публичного контракта и привязка web к реализации api. Отклонено.
