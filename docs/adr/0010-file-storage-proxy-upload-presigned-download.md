# ADR-0010. Файлы: загрузка через API, хранение в приватных бакетах, раздача подписанными ссылками с отдельного origin

Статус: принято. Дата: 2026-10-12. Фаза 3. Обновлено в фазе 3 по аудиту безопасности (`docs/security-review-phase3.md`, SEC-01, SEC-07, SEC-15).

## Контекст

Резюме (PDF/DOCX до 5 МБ) и артефакты (до 10 МБ, квоты проекта) - недоверенные файлы. Правила: тип по сигнатуре и размер проверяются до сохранения, хранение вне каталога приложения, раздача с `Content-Disposition: attachment` и `nosniff`, подписанные ссылки на 5 минут (C-63), лимиты частоты, защита от zip-бомб. Хранилище - MinIO (S3).

## Решение

- Загрузка - multipart в API (`@fastify/multipart`, лимит размера = лимит + 1 байт, один файл), проверка сигнатуры (`file-type` + белый список), проверка ZIP-контейнеров по центральному каталогу без распаковки, минимальный размер 1 КБ, SHA-256; только после этого `PutObject` под случайным ключом в приватный бакет. Квоты проекта - условный `UPDATE` счётчика в одной транзакции со строкой файла; при откате объект удаляется, сироты чистит суточная задача.
- Раздача - presigned GET (5 минут) с `response-content-disposition=attachment` и типом из БД; ссылки на отдельный хост `files.<домен>` (другой origin, без cookie приложения), прокси добавляет `X-Content-Type-Options: nosniff` и `CSP: sandbox`.
- Права проверяет API при выдаче ссылки (участник команды; резюме - только владелец).
- Разбор резюме (SEC-01) - контейнер resume-worker без БД, основного Redis, MinIO и интернета. Файл ему передаёт `worker`: читает объект из MinIO и кладёт байты в задачу очереди `resume-parse` отдельного экземпляра `redis-resume` (только эта очередь, ACL, без персистентности, сеть `resume-net` без выхода наружу). Каждый файл разбирается в одноразовом дочернем процессе под отдельным uid, с пустым окружением, `--disallow-code-generation-from-strings`, лимитами 256 МБ памяти и 15 с; контейнер read-only, non-root, `cap_drop: ALL` (кроме SETUID/SETGID для запуска дочернего процесса), `no-new-privileges`, `pids_limit`, `mem_limit 512m`, `cpus 0.5`. PDF.js (через unpdf) не ниже 4.2.67 (CVE-2024-4367) с `isEvalSupported: false`, `disableFontFace: true`, без внешних ресурсов; mammoth - только `extractRawText`; минимальные версии проверяет CI. Результат - только текст ограниченного формата (`{v, ok, text <= C-26 символов, pages <= C-24}` или код отказа), проверяемый zod в `worker`; подсказки полей извлекаются в `worker` (architecture.md 13.15).
- Проверка содержимого (SEC-15): OOXML с макросами (`vbaProject.bin`), ActiveX, OLE-вложениями и внешними связями не на `https:` отклоняется; ZIP с `..`, абсолютными путями, ссылками и исполняемыми файлами внутри отклоняется; PDF с `/JavaScript`, `/JS`, `/Launch`, `/EmbeddedFile` отклоняется. Интерфейс скачивания предупреждает, что файл загружен участником. ClamAV - вторая очередь.
- Журнал доступа для хоста `files.*` выключен, подписи presigned-ссылок вырезаются из журналов (SEC-07).

## Последствия

- Плюсы: ни один непроверенный байт не попадает в хранилище; скачивание не нагружает API; XSS через загруженный HTML/SVG невозможен (attachment, nosniff, отдельный origin, SVG и HTML не в белом списке).
- Минусы: файлы до 10 МБ проходят через память API (при 30 загрузках в час на пользователя - приемлемо); нужен второй хост в прокси и TLS-сертификат для него.

## Альтернативы

- Presigned PUT напрямую в MinIO: проверка типа возможна только после сохранения (карантин и пост-проверка), сложнее квоты. Отклонено.
- Раздача через API-прокси: лишняя нагрузка и потоковая передача через Node. Отклонено.
- Хранение в PostgreSQL (`bytea`): раздувает БД и резервные копии. Отклонено.
