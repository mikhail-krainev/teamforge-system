# ADR-0013. Транзакции через границу модулей: CLS-контекст, порты и закрытый список T1-T7

Статус: принято. Дата: 2026-10-12. Фаза 3.

## Контекст

Ряд инвариантов охватывает данные нескольких модулей и по требованию оркестратора должен защищаться одной транзакцией: вступление (пользователь из auth, место из teams, дефицит из matching), автодобавление (заявка matching + вступление teams), старт проекта (статус teams + первый этап workspace), завершение (команда teams + этапы и вклад workspace + репозиторий github). Spec 5.5 допускает "явные вызовы интерфейса в одной транзакции там, где это указано в архитектуре". Прямые вызовы teams -> matching и teams -> workspace создают циклы зависимостей.

## Решение

- Транзакция открывается на уровне сценария (контроллер или обработчик задачи) через `TransactionHost` (`@nestjs-cls/transactional` 4.x, адаптер `transactional-adapter-drizzle-orm` 2.x: актуальны на 2026-10-12, требуют Node.js 22+ и `nestjs-cls` 7; запасной вариант - собственный тонкий `TransactionHost` с тем же интерфейсом) и передаётся неявно через `AsyncLocalStorage`; репозитории всех модулей берут текущий клиент транзакции из контекста.
- Методы фасадов, которые обязаны выполняться в чужой транзакции, помечены `@requiresTx` и проверяют наличие активной транзакции (иначе - ошибка программиста).
- Обратные вызовы оформлены портами, объявленными в нижнем модуле: `DeficitPort` (teams объявляет, matching реализует), `TeamLifecyclePort` (teams объявляет, workspace реализует). Привязка реализаций - в `AppModule`; compile-time зависимость остаётся однонаправленной.
- Список межмодульных транзакций закрыт: T1-T7 (architecture.md 2.3). Новая межмодульная транзакция - только через изменение этого ADR.
- Внутри межмодульной транзакции соблюдается глобальный порядок блокировок (ADR-0003). Кроме вызовов из списка T1-T7 допустимы только чтения нижележащих фасадов без блокировок; чужую строку блокирует только метод фасада-владельца с `@requiresTx` (`lockTeam(teamId, 'update' | 'share')`, `lockUserForJoin`), прямой `SELECT ... FOR ...` по чужой таблице запрещён. Данные других модулей, нужные транзакции под блокировкой своей строки (зачёт, architecture.md 10.2), читаются до `BEGIN`.

## Последствия

- Плюсы: инварианты, охватывающие модули, защищены атомарно и проверяемо тестами-гонками; нет циклов импортов; список мест, которые станут сагами при выносе модуля в сервис, известен заранее.
- Минусы: неявный контекст транзакции требует дисциплины (запрет `db` вне `TransactionHost` в коде модулей, правило линтера); порты - дополнительный уровень косвенности.

## Альтернативы

- Саги с компенсациями вместо общих транзакций: сложнее, оставляют окна несогласованности именно в сценариях CC-1..CC-3, которые требуют строгости. Отклонено для T1-T7 (используются для асинхронных реакций, ADR-0005).
- Явная передача `tx` параметром во все фасады: засоряет интерфейсы и даёт возможность забыть параметр; CLS проще. Отклонено.
- Объединить teams и matching в один модуль: противоречит списку модулей оркестратора. Отклонено.
