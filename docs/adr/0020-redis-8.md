# ADR-0020: Redis 8 вместо Redis 7

Статус: принято, 2026-10-15.

## Контекст

В ACL Redis пользователь `default` выключен и не имеет прав (13.16, SEC-10). В Redis 7.4.11 при загрузке AOF блоки `MULTI/EXEC` выполняются от имени `default` и отбрасываются с ошибкой `NOPERM ACLs rules changed between the moment the transaction was accumulated and the EXEC call`. BullMQ пишет в AOF именно такие блоки (Lua-скрипты), поэтому после перезапуска Redis пропадали отложенные задачи (таймеры голосования, `departure-default`) и расписания задач обслуживания. Сквозной тест среза 1 перезапускает Redis, после чего не срабатывал сканер сроков голосования в тесте среза 3.

Проверка 2026-10-15 на одной конфигурации ACL (`user default off`, отдельный пользователь приложения, `appendonly yes`): EVAL с двумя SET и перезапуск. Redis 7.4.11: ключи из EVAL потеряны, в журнале NOPERM. Redis 8.10.2: все ключи на месте, ошибок нет.

## Решение

Перейти на `redis:8-alpine` (8.10.2, образ закреплён по digest) в `docker-compose.yml` и `docker-compose.test.yml`. ACL не меняется: `default` остаётся выключенным и без прав.

## Отклонённые варианты

- Дать `default` права при `off` (`user default off ~* &* +@all`): работает, но расширяет права служебного пользователя; оставлен запасным вариантом, если на Redis 8 проблема вернётся.
- Переустанавливать расписания в воркере после переподключения: отложенные задачи без сканера всё равно терялись бы.

## Последствия

- Redis 8 распространяется под тройной лицензией (RSALv2, SSPLv1, AGPLv3). Платформа использует Redis как отдельный неизменённый сервис, это допустимо; при смене модели размещения проверить лицензию или рассмотреть Valkey.
- В образ входят модули (Bloom и др.), они не используются.
