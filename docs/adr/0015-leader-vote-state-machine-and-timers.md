# ADR-0015. Голосование за тимлида: конечный автомат, снимок избирателей, таймеры BullMQ со сканером

Статус: принято. Дата: 2026-10-12. Фаза 3. Обновлено в фазе 3 по ревью архитектуры.

## Контекст

FR-TEAM-14..21: запуск при выходе, удалении или неактивности тимлида; одно открытое голосование на команду; приём выдвижений 24 ч; срок 72 ч; кворум ⌊N/2⌋+1; досрочное закрытие при > N/2; продление на 48 ч; второй тур при ничьей; нет кандидатов - предложение старшему, затем приостановка; подтверждение победителя за 24 ч. CC-4: "последний голос" против "истечения срока" дают ровно одного тимлида.

## Решение

- Конечный автомат в строке `teams.leader_vote` со статусами `nominating`, `voting`, `runoff`, `confirming`, `offering`, `closed`, `cancelled` и полем `phase_deadline` (architecture.md 8.2). Переходы - только в функциях автомата, каждая в транзакции с блокировками команда -> голосование.
- Одно открытое голосование - частичный уникальный индекс; один голос в раунде - PK бюллетеня.
- Имеющие право фиксируются снимком `vote_eligible` при открытии (N и кворум не "плывут"); вышедший теряет право, поданный голос остаётся.
- Таймеры - отложенные задачи с `jobId` из (голосование, статус, раунд, дедлайн); устаревший таймер распознаётся сравнением с текущим состоянием и ничего не делает. Сканер раз в минуту ставит задачи для просроченных дедлайнов (страховка от потери Redis).
- Подтверждение победителя и предложение старшему - `vote_offer` с одним активным предложением на голосование; срок ответа старшего - 24 ч (решение архитектуры, Р-12).
- Ничья второго тура: стаж в команде, затем `crypto.randomInt` с записью в журнал команды. Кто за кого голосовал, не раскрывается.
- Снятие кандидатуры - `withdrawCandidacy` (`withdrawn_at`) в фазах `nominating`, `voting`, `runoff`, в `confirming` равно отказу; голоса за снятого не учитываются; без подтверждённых кандидатов голосование по сроку уходит в `offering`.

## Последствия

- Плюсы: все пограничные случаи - явные переходы с тестами; конкурирующие голос и таймер сериализуются одними и теми же блокировками; часы подменяются в тестах.
- Минусы: автомат из 7 состояний требует полного покрытия (95% по spec 5.9); снимок избирателей - решение архитектуры, не прописанное в spec (Р-14).

## Альтернативы

- Вычислять фазу из меток времени без статусов: сложнее понять, что уже обработано, выше риск двойного исхода. Отклонено.
- Пересчёт N при каждом выходе: кворум меняется посреди голосования, трудно объяснить участникам. Отклонено.
- cron-опрос без отложенных задач: точность до минуты достаточна, но отложенные задачи дают точность и меньше нагрузки; сканер оставлен как страховка. Принято в комбинации.
