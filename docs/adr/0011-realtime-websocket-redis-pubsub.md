# ADR-0011. Реальное время: WebSocket в процессе api, Redis pub/sub, события-инвалидации без данных

Статус: принято. Дата: 2026-10-12. Фаза 3.

## Контекст

Стек: WebSocket через Redis pub/sub. Чата нет (вторая версия); нужно обновлять экраны (разбор резюме, голосование, чек-лист, лента, уведомления) без опроса. Несколько экземпляров api за прокси; права на данные команды меняются (выход, исключение, удаление аккаунта).

## Решение

- `@fastify/websocket` на маршруте `/api/ws` в процессе api; аутентификация cookie сессии при рукопожатии, проверка `Origin`.
- Каналы `user:<id>` (только сам пользователь) и `team:<id>` (активный участник; проверка через `TeamsApi.assertMember` при подписке и повторно раз в 5 минут).
- Сообщения - события-инвалидации: тип, идентификаторы, версии, статусы. Никаких ПД и текстов; клиент перечитывает данные через REST с обычной проверкой прав.
- Источник событий - outbox (ADR-0005): ретранслятор публикует в Redis `rt:<канал>`; каждый экземпляр api держит одну подписку `PSUBSCRIBE rt:*` и раздаёт локальным сокетам.
- Отзыв: события `member_left`/`member_excluded`/`session.revoked` отписывают или закрывают соединения на всех экземплярах.
- Лимиты соединений, подписок и входящих сообщений на пользователя.

## Последствия

- Плюсы: утечка или потеря события не раскрывает и не портит данные (клиент всё равно читает REST); экземпляры api взаимозаменяемы; нет второй модели прав.
- Минусы: после события - дополнительный REST-запрос; доставка "не более одного раза" (при переподключении клиент перечитывает экран); `PSUBSCRIBE rt:*` доставляет каждому экземпляру все события (при масштабе MVP - сотни в минуту - приемлемо; при росте - подписка по каналам).

## Альтернативы

- Socket.IO с Redis-адаптером: свой протокол и клиент, больше зависимостей ради функций (комнаты, подтверждения), которые не нужны. Отклонено.
- Server-Sent Events: проще, но стек фиксирует WebSocket, а для будущего чата нужен двунаправленный канал. Отклонено.
- Полезная нагрузка с данными: дублирует проверку прав и сериализацию в двух местах. Отклонено.
- Опрос (polling): нагрузка и задержка. Отклонено.
