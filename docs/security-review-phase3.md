## Границы доверия (модель угроз, кратко)

| Граница | Что входит недоверенным | Основные угрозы (STRIDE) |
|---|---|---|
| Браузер -> Caddy -> api `/api/v1`, `/api/auth/*` | тела, query, cookie, `X-Forwarded-For`, `Origin`, `callbackURL` | S (сессии), T, E (IDOR), D (лимиты) |
| Браузер -> web (Next.js SSR) -> api | заголовки, проброс cookie | E (обход middleware), S (подмена IP) |
| GitHub -> вебхук | подписанное тело, неподписанный `X-GitHub-Delivery`, порядок доставки | T, R, D |
| Setup URL GitHub App | `installation_id`, `state`, `code` | S, E (чужая установка) |
| Загрузка файлов -> MinIO -> resume-worker | PDF/DOCX/ZIP/PPTX | E (RCE в парсере), D (бомбы) |
| worker -> внешние URL (ссылки, релизы) | URL пользователя, DNS, редиректы, тело ответа | I/E (SSRF) |
| WebSocket `/api/ws` | подписки на каналы | I (чужие события), D |
| Redis (сессии, очереди, кэш токенов) | всё, что пишет любой процесс с `REDIS_URL` | S, T, E |
| Резервные копии, журналы | ПД, токены в URL | I, 152-ФЗ |

## Что сделано хорошо

- Ключ идемпотентности привязан к пользователю (PK `(user_id, key)`), захват атомарный, `request_hash` включает `operationId`: подмена ответа другого пользователя невозможна.
- Вебхук: проверка `X-Hub-Signature-256` по сырому телу за постоянное время до разбора, дедупликация по `delivery_id`, zod-проверка полезной нагрузки, время по `received_at`, атрибуция по числовым id.
- GitHub App только с правами чтения, пользовательский токен сразу отбрасывается, токен установки не пишется в БД и кэшируется зашифрованным (AES-256-GCM с версией ключа).
- Загрузка через API с проверкой сигнатуры до записи в хранилище, защита от zip-бомб по центральному каталогу, случайные ключи объектов, раздача с отдельного origin с `attachment`, `nosniff`, `CSP: sandbox`, ссылки на 5 минут.
- Токен приглашения во фрагменте URL и в теле POST, в БД хранится только SHA-256.
- События WebSocket не содержат данных, только id и версии; проверка `Origin` при рукопожатии; лимиты соединений.
- Входящие URL в контракте ограничены `^https://` (`portfolioUrl`, `linkUrl`, `externalUrl`), поэтому XSS через `javascript:` исключён.
- SSRF-клиент подключается к проверенному IP (защита от DNS rebinding) и проверяет каждый редирект заново.
- Проверка окружения zod при старте с выводом только имён переменных; `/metrics` не публикуется.
- Сага удаления с журналом без ПД, мгновенный отзыв сессий, отзывы без `author_id` в API, rewards изолирован от profiles правилом `dependency-cruiser`.
- Ошибки RFC 9457 без деталей для 500; 404 вместо 403 там, где нельзя раскрывать существование.
