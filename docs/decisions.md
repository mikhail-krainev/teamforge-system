# Решения фазы 0

Дата: 2026-10-12. Стек, архитектура, границы MVP и правила наград заданы в `docs/orchestrator.md` и здесь не повторяются.

## 1. Аудитория и язык интерфейса

- Аудитория: студенты и начинающие специалисты из России и СНГ.
- Язык интерфейса: русский.
- Все строки интерфейса выносятся в словари i18n с первого среза, чтобы английский добавлялся без правки компонентов. Английская локализация входит во вторую версию.
- Даты и время хранятся в UTC, отображаются в часовом поясе пользователя. Часовой пояс указывается в профиле и используется в подборе.

## 2. Способ входа

- Основной вход: GitHub OAuth. Учётная запись GitHub всё равно нужна для учёта вклада в рабочем пространстве.
- Запасной вход: email (ссылка для входа или пароль, выбор в фазе 1 по результатам исследования библиотек авторизации).
- Пользователь, вошедший по email, привязывает GitHub перед вступлением в команду.
- Авторизация на готовой проверенной библиотеке, своя не пишется.

## 3. Размещение

- Один VPS с Docker Compose: web, api, воркеры BullMQ, PostgreSQL, PgBouncer, Redis, MinIO, обратный прокси с TLS.
- VPS размещается в дата-центре на территории России (следует из п. 4).
- Архитектура остаётся без состояния на стороне API, чтобы позже перейти на несколько экземпляров или управляемые сервисы без переписывания.
- Резервное копирование базы и хранилища описывается в фазе 7.

## 4. Персональные данные

- Требования 152-ФЗ.
- Персональные данные пользователей из России хранятся и обрабатываются на серверах в России, включая резервные копии.
- При регистрации пользователь даёт явное согласие на обработку персональных данных. Публикуется политика обработки персональных данных.
- Удаление по запросу пользователя: профиль, резюме, отзывы о нём, загруженные файлы. Вклад в чужие проекты обезличивается, а не удаляется, чтобы не ломать историю команды.
- Резюме и отзывы: доступ по правам, отзыв виден только тому, о ком он написан, без имени автора.
- Токены GitHub хранятся зашифрованными.
- Передача данных за рубеж: GitHub API получает только данные, нужные для интеграции (логин GitHub, репозиторий). Это фиксируется в политике обработки и в согласии. Юридическая проверка формулировок выходит за рамки разработки и записывается в открытые вопросы.

## Открытые вопросы
