# S2-01: Better Auth in NestJS 12 + Fastify, result of the prototype

Verdict: the prototype works on the key points. Schema `auth` through Drizzle `pgSchema` is kept (the `auth_` prefix fallback is not needed).

## Versions

better-auth 1.7.7 (exact), drizzle-orm 0.45.4, @nestjs/* 12.1.3, fastify 5.12.5, ioredis 6.0.0, uuidv7 1.2.1, Redis 7, PostgreSQL 16 (through PgBouncer, transaction mode).

## What works (test: `auth-spike.test.ts`, 10 tests green on the test stack)

- Mounting: not a Fastify catch-all but explicit Nest routes (`internal/controllers/auth.controller.ts`) that turn the Fastify request into a Web `Request`, call `auth.handler` and copy status, headers (several `Set-Cookie` kept) and body back (`internal/better-auth/web-bridge.ts`). Every route has `@Authz(operationId)` from the contract, so AuthzGuard and ValidationGuard (body schema, `CallbackPath`) run before the library. Library routes that are not listed (`/list-sessions`, ...) answer 404, so nothing of the library is exposed by accident. `x-forwarded-for` is overwritten with Fastify's trusted-proxy aware `request.ip`.
- Tables in schema `auth` via `pgSchema` (`internal/schema/auth.ts`), migration `drizzle/0002_auth_tables.sql` generated by drizzle-kit (no `getMigrations`). Ids are UUID v7 (`advanced.database.generateId`), checked by regex in the test.
- Sessions only in Redis: `secondaryStorage` with prefix `better-auth:` (matches the ACL `~better-auth:*`), `auth.session` stays empty. The adapter needs `get/set/delete/getAndDelete/increment`; `getdel` and a Lua `INCR+EXPIRE` pass the test ACL profile (`+@all -@dangerous`).
- Flow login -> cookie -> getSession -> signOut -> session invalid; sign-out without a cookie is 401 (AuthzGuard, actor `authenticated`).
- `revokeUserSessions`: the library function is `internalAdapter.deleteUserSessions(userId)` (the admin plugin only wraps it; `deleteSessions` takes tokens, not a user id). Wrapped as `SessionRevoker.revokeUserSessions` (`internal/services/session-revoker.ts`). The test shows that all 3 sessions and the `active-sessions-<userId>` list disappear and another user's session survives.
- `encryptOAuthTokens`: `account.access_token`/`refresh_token` are stored as ciphertext (not `ghu_`/`ghr_`).
- GitHub App sign-in (user-to-server OAuth) against a minimal double (`github-double.ts`): authorize -> state -> code exchange -> `/user` + `/user/emails` -> session; only a verified email counts. `github_user_id` and `github_login` are filled on user creation.
- Cookie: `better-auth.session_token` (HttpOnly, SameSite=Lax, Path=/, no Domain); in production `useSecureCookies` gives `__Secure-better-auth.session_token` (Secure). The web `proxy.ts` expects exactly these two names. A `__Host-` prefix (SEC-23) would need `advanced.cookies.session_token.name` plus a change in web; not done.
- Origin/CSRF: Better Auth rejects a foreign Origin (403) and a request with a cookie but without Origin/Referer.

## What does not work as written, and the decisions

1. The built-in `github` provider has hard-coded URLs (`github.com`, `api.github.com`), so it cannot be pointed at a double. Decision: GitHub is registered through the `genericOAuth` plugin with `providerId: 'github'` (own code exchange and `/user`, `/user/emails` in `github-provider.ts`). Routes stay `sign-in/social`, `link-social`, `callback/github`. Base URLs come from the new optional variables `GITHUB_OAUTH_BASE_URL` / `GITHUB_API_BASE_URL` (what `test/fakes/github-server.ts` `githubEnv()` sets); the configuration refuses them when `NODE_ENV=production`.
2. Better Auth switches the Origin/CSRF check OFF when `NODE_ENV=test`. Fixed with `advanced.disableOriginCheck: false` and `disableCSRFCheck: false`. Tests must not rely on the default.
3. Better Auth validates the Drizzle schema at the first request and wants `account.password`. The column is nullable and never written (no passwords).
4. Provider-profile fields reach a new user only for additional fields with `input: true`. `githubUserId` and `githubLogin` therefore have `input: true`; `status`, `isAdmin`, `locale` stay `input: false` (never settable from a profile or a request). No exposed route accepts user input. For account linking (S2-05) the same fields are set in an `account.create.after` hook.
5. `callbackURL` stays a relative path in the Location header (`/profile`, not `APP_ORIGIN/profile`); correct with one domain for web and API behind the proxy.
6. Token encryption uses the Better Auth secret (`BETTER_AUTH_SECRET`), as architecture 13.8 says; Better Auth has no separate key for it (`secrets: [...]` sets signing and encryption together). `DATA_ENCRYPTION_KEY` is not used for OAuth tokens; if the orchestrator wants it, set `secrets: [{ version: 1, value: DATA_ENCRYPTION_KEY }]`, which also makes it the cookie signing key.
7. The test session stand-in (`x-test-user`) and the real authenticator use the same provider token. `createTestApp` now overrides it with `TestSessionAuthenticator`, which uses the header when present and delegates to `BetterAuthSessionAuthenticator` otherwise.

## Side fixes found on the way

- `.dependency-cruiser.cjs`: the rule `no-cross-module-internal` used `$1` (the `(^|/)` group) instead of the module name, so it flagged a module's own files as soon as real code appeared. Now `$2`.
- `tx.test.ts`, `migrations.test.ts`: used a stand-in `auth."user"` and a fixed migration count; adjusted for the real tables.

## Not covered by the prototype

Magic link plugin (S2-04), hooks for email normalisation and `GITHUB_ALREADY_LINKED` (S2-05), the platform rate limit hook in front of `/api/auth/*`, `__Host-` cookie prefix, the account cookie / `freshAge` check for `requestDeletion` (S2-07). Deletion cancel link for web: `/deletion/cancel#token=...` (token in the fragment, POST to `cancelDeletionRequest`).
